一套能被拆开

01 / 设计原则

先定义边界，
再让系统生长。

这些原则直接约束包依赖、数据布局、错误暴露和工程取舍， 也决定了哪些捷径不能被接受。

01

内核克制

Kernel 只负责启动、包加载、服务注册、子系统生命周期和主循环。 具体能力由包提供，产品组合由 workspace manifest 决定。

THIN SHELL
02

合同明确

包依赖、服务提供和版本约束都是显式的。跨包协作通过接口完成， 不在领域包之间复制具体实现，也不把服务注册表带进热循环。

EXPLICIT CONTRACTS
03

数据优先

热路径使用连续数据和批处理。避免托管分配、锁、逐实体接口调度， 也避免为了短期的开发便利破坏长期的内存行为。

ZERO-OVERHEAD PATHS
04

正确性可证明

生命周期、GPU 资源和跨线程状态必须有可观察的完成条件。 禁止用任意等待、吞掉异常或关闭验证来换取表面稳定。

STATE, NOT TIMING

02 / 系统分层

每一层都只回答
自己该回答的问题。

从加载包图到提交绘制命令，责任沿着清晰的层次向下传递。 上层选择产品与内容，底层保证资源、同步和呈现。

05

Hosts

EDITOR · RUNTIME · LAUNCHER

Editor 使用编辑器宿主承载原生 UI 与虚拟表面；独立运行时通过 Win32 创建并驱动主窗口；Launcher 管理项目元数据与启动。

com.arisen.editor com.arisen.platform.desktop
04

Application

GAMEPLAY · ASSETS · STREAMING

游戏逻辑和内容以包为单位组织。世界单元具备受控的 CPU 驻留过程， 资源交接发生在帧边界，最终 GPU 释放由提交票号决定。

com.arisen.ecs com.arisen.resources game packages
03

RenderGraph

PASS DAG · PIPELINE · TASKGRAPH

Pass 声明输入和输出，图负责排序与资源生命周期。 通用管线定义具体拓扑，CPU 侧构建与部分工作可以由任务图并行推进。

com.arisen.dag com.arisen.rendering com.arisen.generic-renderpipeline
02

RHI

RESOURCES · SYNC · PRESENTATION

后端把渲染图翻译成 Vulkan 资源、管线、命令和同步。 上层共享 RHI 合同，具体图形后端保留为可选择的产品组合。

com.arisen.rhi.vulkan.native shared RHI interfaces

01

声明依赖

每个 Pass 明确读写资源，图结构在编译与执行边界保持可检查。

02

控制资源

资源生命周期由图统一管理，为屏障、剔除和复用留出正确位置。

03

并行准备

不相互依赖的工作可以提交给 TaskGraph，CPU 准备不再串行等待。

04 / 运行时

并发的前提，
是所有权清楚。

Arisen 把线程边界作为架构的一部分处理。 世界加载可以并行准备，但 ECS、UI、RHI 和命令录制各有明确归属。

Host 拥有帧节奏。主窗口最小化时，引擎线程停在窗口消息队列上， 恢复时在进入下一帧前重新对齐帧时钟。

FRAME BOUNDARY

主线程与宿主

  • + 拥有 UI 与主窗口生命周期
  • + 在帧边界推进资源驻留
  • + 决定提交与呈现时机
WORLD WORKERS

数据准备线程

  • + 读取并验证资产载荷
  • + 取得带代际校验的驻留租约
  • − 不修改 ECS 或 UI
  • − 不创建 RHI 资源或录制命令
DEFERRED RELEASE

释放跟随提交票号

GPU 资源不会因为 CPU 侧不再使用就立刻销毁。 释放队列绑定到明确的设备代际，等待最后一次相关提交完成后再回收。

02

启动、窗口、呈现和关闭路径必须留下可检查的日志与所有权状态。
