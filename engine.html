ENGINE / 设计与实现概览

系统可组合，
责任有归属。

Arisen 用包图组织产品，用连续数据与批处理组织运行时，再用明确的所有权连接模拟、渲染和工具。重点不是把能力集中在一个巨大内核，而是让系统能够沿着清楚的合同协作。

这是当前工程实现的概览。源码仍在非公开开发阶段；接口细节与代码分析将逐篇审定后公开。

01 / 包与产品

能力由包提供，
产品由组合决定。

Workspace 不是 Package。前者选择产品需要的包与配置，后者提供实际代码、资产、服务与子系统。

manifest.jsonWorkspace / 产品选择
Editor编辑与创作
Development独立运行与诊断
Production烘焙内容部署
  1. 01解析包依赖与版本约束
  2. 02检查分层、服务与所需能力
  3. 03生成工程与解析后的运行清单
  4. 04按包图加载，初始化子系统，交给 Host

这是职责流程示意，不是完整依赖图。Samples 和测试等产品也通过各自 Profile 选择能力。

内核负责生命周期

ArisenKernel 管理启动、包加载、服务注册与子系统。渲染、资源、编辑器和游戏功能由包提供，不固化为内核里的功能开关。

构建与运行分两道检查

ArisenBuildTool 根据元数据解析和生成工程；运行时再检查选中的包约束、服务注册与原生载荷，避免把生成成功当成可直接启动。

共享合同，显式选择实现

领域包依赖共享接口，产品组合选择具体提供者。服务通常在粗粒度初始化边界解析并缓存，不在实体内循环中反复查询。

包化降低的是组合与推理的耦合，不意味着任意包能够脱离依赖运行，也不承诺运行时任意热插拔。

02 / 渲染与 RHI

先声明读写关系，
再组织执行与提交。

Generic Pipeline 选择具体拓扑与质量设置，RenderGraph 处理依赖和资源状态，Vulkan RHI 承担原生资源、命令、同步与输出。

GENERIC PIPELINE / 阶段归组示意 · 非逐帧捕获
01 / LIGHT & SKY

阴影与天空

方向光阴影与 Environment Sky，为场景绘制提供阴影输入和 HDR 背景。

02 / SCENE

场景绘制

静态网格、地形／植被扩展与透明绘制。需要时生成速度缓冲。

03 / POST

后处理

可选大气与 Bloom，随后 Tonemap，并按配置使用 TAA 或 FXAA。

04 / OUTPUT

叠加与输出

选入的运行时 UI 叠加后，交给原生交换链或编辑器共享纹理输出。

上述分组反映当前管线的职责，不表示所有 Pass 必定启用，也不是一条严格串行的 DAG。可选 Pass 由设置和包组合决定，实际执行依赖来自资源读写声明。

GRAPH / 依赖

图承担规划

图编译排序资源依赖、规划状态转换和瞬态生命周期，并剔除无用 Pass。稳定拓扑与工作记录复用，让资源和执行规划有明确位置。

RHI / 合同

后端承担执行

资源通过句柄表达，托管层与原生层通过明确的 ABI 协作。Vulkan 提供当前具体实现，图形合同与提供者分离，为后续扩展保留边界。

JOBS / 调度

任务有独立上下文

RenderGraph 使用共享任务执行器处理录制工作。CPU 准备、原生命令准备与 GPU 执行分别建模，在所需的消费边界观察完成。

03 / 线程与数据

数据可以交接，
所有权不能含糊。

模拟、渲染、共享 Worker 和编辑器 UI 不是同一个“主线程”。职责归属决定谁能修改状态，以及什么时候能够回收它。

SIMULATION / HOST

模拟与运行时宿主

  • 推进模拟、场景需求与 ECS 激活
  • 提取数据，发布保留的渲染帧快照
  • 独立运行时保持 Win32 窗口消息与帧节奏的宿主归属
RENDER OWNER

渲染所有者

  • 消费帧快照，组织图执行与 GPU 提交
  • 负责 GPU 资源准备、发布和生命周期
  • 处理表面控制、呈现和设备代际相关工作
SHARED WORKERS

共享任务执行器

  • 为模拟与渲染提供独立执行上下文
  • 后台分区准备受预算约束的不可变 CPU 数据
  • 后台资源任务不直接修改 ECS、UI 或录制 RHI 命令
EDITOR UI

Avalonia UI 与合成

  • 编辑器模拟由 EditorEngineRunner 推进
  • Avalonia 拥有 UI、控件和合成器交接
  • 共享纹理与信号量必须完成明确的生产者／消费者归还

CPU 用完，不代表 GPU 已经用完。

保留的帧数据、资产读租约和 GPU 资源有不同生命周期。提交票号必须在正确的设备／队列代际中观察完成，不能用多等几帧替代释放条件。

ECS / 连续数据

组件按池存储

组件池以连续稠密数据配合稀疏索引。系统处理数据范围，结构修改通过命令缓冲在拥有者边界回放。

REUSE / 存储复用

稳定工作不反复重建

稳定任务拓扑、执行记录和帧槽尽量复用。热路径低分配通过针对性测试与分析逐项核对，关注实际内存行为。

CONTROL / 完成条件

等待有明确对象

资源上传、队列完成、帧槽归还与 UI 合成同步分别处理。移除资产上传阻塞，不等于取消必要的生命周期同步。

04 / 资产与流送

从作者文件，
到可部署的内容。

资产身份、Cook、驻留与 GPU 资源是同一条生命周期上的不同环节。世界流送不仅是异步读文件，还要管理激活、预算与退出。

  1. 01
    导入与作者数据

    源资产与元数据由资产管线登记；编辑器文档保留明确的源访问权限。

  2. 02
    Cook 与依赖闭包

    按类型生成经过格式校验的运行数据，收集项目启动和内容所需的依赖。

  3. 03
    驻留与准备

    CPU 载荷、GPU 准备和发布受预算与代际约束。世界单元等待资源就绪，再由模拟拥有者激活。

  4. 04
    部署、使用与释放

    部署目录通过相对路径、大小与哈希校验。最后一个使用者退出后，GPU 回收仍等待相关提交完成。

创作与运行有不同权限

普通 Development／测试运行默认选择 Cooked 数据。Editor 的作者源访问由编译策略决定；诊断源访问是显式、受限的入口，不是部署版本的回退路径。

Production 使用可搬移的运行内容目录，不依赖作者机器上的工作区源路径。世界、地形与植被分别有状态、内存、画面和关闭路径的验证范围。

05 / 编辑器与工具

编辑真实内容，
而不只是操作外壳。

Avalonia 拥有编辑器 UI，包与服务连接引擎。工具的重点是文档修改、撤销重做、保存与实际运行结果之间的一致性。

AUTHORING / 创作路径

资产、文档与命令

  • Content Browser 管理项目与包资产根
  • 场景／材质编辑连接真实资产与文档服务
  • 撤销重做与保存重开检查实际状态，而非只检查 UI 文本
VIEWPORT / 图形交接

双视口与真实宿主

  • Scene 与 Game 视口消费引擎共享纹理输出
  • 尺寸变化、消费者归还与设备代际重建有明确交接
  • RenderDoc 激活通过完整图形代际重建，不向运行中的后端隐式注入

部分创作流程已有真实场景门禁，完整“打开项目到构建产品”的编辑器工作流仍在完善。已验证的流程与后续作者能力分别跟踪。

06 / 工程验证

每一类结论，
都需要相应的证据。

构建、状态验证、真实运行和性能分析回答不同问题。测试绿灯不替代画面审阅，GPU 捕获也不自动证明 CPU 调度收益。

CONTRACTS / 合同

包与实现边界

包图、版本、服务、绑定与生命周期测试检查错误配置、失败传播和清理条件。

说明合同在测试范围内成立，不代表所有真实宿主路径已通过。

SCENARIOS / 场景

真实运行路径

运行时启动、世界／地形流送、部署搬移和编辑器双视口检查实际输出与所有权。作者场景覆盖资产、文档、命令和保存重开。

说明对应场景的状态与结果，不是完整商业制作能力保证。

CAPTURES / 分析

Tracy 与 RenderDoc

CPU/GPU 跟踪与图形捕获用于核实线程归属、同步、资源与执行成本。完整性按捕获实际包含的数据声明。

性能结论需固定负载与可对比基线；没有数据就不报提升比例。

阶段结论和具体捕获会在对应技术文章中说明基线、环境与限制；画面、功能状态与性能数据分别审阅。

07 / 自动化与 AI 协作

让工具能够参与，
让决定保持可审阅。

AI 友好首先来自可读取的元数据、可定位的包边界与可重复执行的验证。它是研发协作方式，不是“一个提示就完成游戏”的产品承诺。

从元数据定位范围

工作区、包依赖、服务与子系统有明确描述；工具可以先识别修改范围，再深入实现。

从验证返回真实结果

任务可以提出候选代码或资产，输出仍需经过对应的合同、场景和人工审阅。架构决策与最终接受权保留在开发者手中。

编辑器 AI 操作、权限、扩展和生成流程存在独立标准与演进计划，不能将这些设计文件理解为功能已经全部落地。

08 / 方向与边界

先连成完整路径，
再扩展能力范围。

下一步继续完善可重复的创作和验收，而不是以功能数量替代工程成熟度。路线随需求与验证结果调整，不是发布日期承诺。

FOUNDATION / 已建立的基础

内核到运行输出

  • 包组合与构建生成
  • Vulkan 与图形所有权路径
  • 内容驻留和流送样本
  • 编辑器宿主与场景门禁
FOCUS / 持续完善

创作、调度与表达

  • 编辑器作者操作与构建闭环
  • 渲染并行范围和阶段证据
  • 可复现的内容生产流程
  • 经代码与文字审阅的技术文档
LIMITS / 尚不承诺

如实标明边界

  • Windows / Vulkan 以外的完整支持
  • 任意包热插拔与成熟公共版本
  • 完整 AI 生成游戏或商业制作闭环
  • 没有可对比实测的性能领先结论

EVOLUTION / 架构演进主线

  1. 后端模块探索

    将图形接口与具体实现分开。

  2. 句柄与 C ABI

    明确资源身份和托管／原生交接。

  3. 包化微内核

    将产品组合交给包图与构建工具。

  4. 所有权与创作路径

    继续连接并发、内容、工具和验证。
